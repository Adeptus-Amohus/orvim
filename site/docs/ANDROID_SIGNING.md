# Постоянная подпись Android

С выпуска 0.4.46 существует постоянный release-ключ Orvim. Повторно создавать или заменять его при следующем выпуске нельзя. Package ID остаётся `local.lifeos.client`; пользовательские данные ради названия приложения не меняются.

- Сертификат: `CN=Orvim, OU=Application Release, O=Orvim`.
- Алгоритм: RSA 4096; срок действия до 2 ноября 2056 года.
- SHA-256 сертификата: `69769e705d33225d37d62da35c3d549c219d6235cf658118a16649056591c386`.
- APK 0.4.46 использует подпись v2/v3; проверены `apksigner verify` и 16-КиБ выравнивание.

Это открытые сведения о сертификате, а не закрытый ключ или пароль. Прежние тестовые APK до 0.4.45 использовали тестовый сертификат; новый release APK не устанавливается поверх них. [Порядок перехода с сохранением данных](INSTALLATION.md#переход-со-старого-тестового-apk): переносимая копия с паролем → проверка восстановления → переустановка → восстановление данных.

## Резервирование существующего ключа владельцем

Храните защищённую независимую копию **существующего keystore** вне рабочего компьютера, а alias и пароль — отдельно в надёжном менеджере паролей или офлайн-хранилище. Проверьте, что копия открывается существующим паролем, без создания нового ключа. Keystore, пароли и закрытые ключи не публикуются и не передаются в чате.

Локальный DPAPI XML привязан к пользователю Windows и сам по себе не позволяет восстановить пароль на новом компьютере. Копирования одного XML недостаточно. При переносе среды сборки восстанавливается исходный keystore с тем же сертификатом; новый ключ не создаётся.

Подпись APK, ключ шифрования личной базы, подпись манифеста обновлений и Authenticode Windows — разные механизмы. Сертификат APK не отменяет предупреждений Windows.
