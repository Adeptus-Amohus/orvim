# Проверка Orvim 0.4.38

Дата: 5 ноября 2026. Локальный Android ARM64 APK, без публикации и без сборки Windows.

## Что проверено

- TypeScript: `npm run typecheck` — успешно.
- Модель виджетов и сохранение при закрытии: `node --test tests/widgets.test.mjs tests/window-close.test.mjs` — 9 тестов успешно.
- `node tests/browser-widget-journal.cjs` — перенос мысли, задачи, еды и отметки выполнения из журнала в базу; повторный импорт без дублей; квитанции сохраняются после перезапуска.
- Gradle: debug APK, Android instrumentation APK и release APK; release lint — успешно.
- Android 16 / API 36, AVD LifeOS_API_36, отдельный временный пользователь в read-only сеансе эмулятора: `WidgetNativeTest` — 3 теста успешно, финальный прогон 18,658 с.
- Нативное окно мысли: ввод, добавление, закрытие окна; запись присутствует в зашифрованном журнале и отсутствует в открытом виде в SharedPreferences.
- Нативное окно питания: ручная запись 105 ккал сохраняется, сумма в виджете обновляется со 100 до 205 ккал.
- Настоящий Android AppWidgetHost: расписание 340 × 470 и 280 × 320 dp, питание 150 × 150 dp, мысль 170 × 56 dp. Снимки проверены визуально: обычные текстовые строки вместо растягиваемой картинки; компактная мысль с целой рамкой и прозрачным фоном; кнопки питания видны при минимальной высоте.
- Список часов содержит 24 строки; прокрутка от начала к концу суток и обратно работает. Нажатие галочки через реальный PendingIntent строки сохраняет изменение в фоне. Эти действия не создают MainActivity.
- Найденный при разработке ANR устранён: чтение коллекций выполняется в onDataSetChanged, обновление виджетов вызывается вне блокировки хранилища. Финальные нативные тесты проходят.
- Итоговый подписанный release APK установлен поверх debug-сборки на эмуляторе. Холодный запуск MainActivity успешен; главный экран отрисован. В журнале запуска нет FATAL EXCEPTION или ANR приложения.
- Проверены идентификатор local.lifeos.client, версия 0.4.38 / 4038, ARM64, прежний сертификат 0.4.37, ZIP-выравнивание 16 КБ, сегменты ELF LOAD с выравниванием 0x4000, совпадение библиотеки и текущих frontend-ресурсов с APK.
- APK 0.4.37 сохранён без изменений; SHA-256: `017FF239D0F9EBFC57E902A0B495B358A42EA6B0E94AED9FD1DF836F522A4852`.

## Границы проверки

Нативные сценарии автоматизированы на debug-сборке с теми же исходниками Android. Подписанный release отдельно установлен и запущен. Это не проверка на физическом телефоне и не гарантия одинаковой сетки у всех лаунчеров. Старые виджеты после обновления нужно удалить и добавить заново; Orvim один раз открыть для обновления данных виджетов.

Реальный запрос к OpenAI, DeepSeek или Gemini не выполнялся: в тестовом профиле нет пользовательского API-ключа. Настройку и сетевой ответ выбранного пользователем провайдера нужно проверить на телефоне. Ручное добавление еды проверено независимо от ИИ.

Записи виджетов сразу сохраняются локально в зашифрованном журнале и учитываются виджетами. Перенос в основную базу и включение в её резервные копии/синхронизацию происходит при следующем открытии Orvim. Это описано также в заметках к версии.
