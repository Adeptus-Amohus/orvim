# Аудит безопасности Orvim — 25 октября 2026

Проверены текущие исходники, а не ранее выпущенные APK/EXE. По решению пользователя внедрение шифрования личной базы отложено; ниже отдельный план. Личные записи и действующие ключи для проверки не использовались.

## Проверенные существующие ограничения

- Текст мыслей, задач и ответов ИИ выводится через текстовые DOM-узлы. В рассмотренных местах `innerHTML` используются статические шаблоны, числовые значения или проверенные цвета. Тестовые `<script>`, `onerror`, SVG, iframe и `javascript:` не создали исполняемые узлы в проверке Markdown.
- При импорте и синхронизации проверяются поля, числовые диапазоны, размеры и опасные ключи `__proto__`, `constructor`, `prototype`. Запись в SQLite использует параметры; динамические имена таблиц выбираются из кода.
- Изменения ИИ проходят предпросмотр и валидацию. Они не дают модели доступ к настройкам, произвольным системным командам или чтению ключей.
- CSP не разрешает внешние скрипты и iframe; capabilities не предоставляют удалённым сайтам IPC. Открываемые ссылки ограничены HTTP(S), без логина/пароля в URL. Внешние страницы и загружаемые пользователем документы не становятся доверенными от этого ограничения.
- Обложки скачиваются с разрешённых хостов с проверкой каждого redirect, размера и сигнатуры растрового файла. SVG не принимается как обложка.
- LAN использует сопряжение, одноразовый ограниченный по времени код, лимит попыток, проверку challenge, ограничение размеров сообщений и XChaCha20-Poly1305. WebDAV использует HTTPS и шифрование журнала. Тесты проверяют повреждение шифротекста, неверный контекст, сопряжение и отзыв устройства.
- Установщик обновления требует подписи манифеста Ed25519 и совпадения размера/SHA-256 пакета. Неподписанная проверка публичных выпусков не предоставляет автоматическую установку.
- Ограниченный поиск шаблонов приватных ключей и распространённых токенов в исходниках/ресурсах/скриптах не дал совпадений. Это не полное сканирование Git-истории и не доказательство отсутствия всех видов секретов.

## Шифрование сейчас

| Данные                                                                 | Текущее состояние                                                                                                                                 |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ключи API/OAuth                                                        | Windows DPAPI CurrentUser; Android AES-GCM с ключом Android Keystore. Ключ не возвращается интерфейсу через публичную операцию чтения.            |
| LAN/WebDAV в передаче                                                  | Аутентифицированное шифрование XChaCha20-Poly1305; WebDAV дополнительно HTTPS.                                                                    |
| Основная SQLite, локальные журналы LAN/WebDAV, IndexedDB предпросмотра | Не зашифрованы приложением.                                                                                                                       |
| Обычные JSON/SQLite-копии, экспорт CSV, сохранённые вложения           | Не зашифрованы приложением. Секреты подключений исключаются из штатных копий, но секрет, вручную вставленный в заметку, остаётся обычным текстом. |

Системная защита ключей не защищает от вредоносной программы, уже работающей с достаточными правами в том же аккаунте, скомпрометированной ОС или чтения разблокированной памяти приложения.

## Отдельный план шифрования (не внедрён)

1. Согласовать разблокировку: ключ устройства или пароль; отдельно определить восстановление после потери устройства. Не использовать PIN в качестве сырого ключа.
2. Выбрать поддерживаемый способ шифрования SQLite для Windows/Android, проверить лицензирование и сборку. Покрыть основную базу, WAL/SHM/временные файлы, локальные журналы синхронизации, обложки и настройки; одной зашифрованной JSON-копии недостаточно.
3. Хранить случайный ключ базы через DPAPI/Keystore. Для переносимых копий — отдельный формат с аутентифицированным шифрованием, солью, параметрами KDF и защитой от повреждения. Парольную KDF выбрать и измерить на слабом Android; ключ не помещать рядом с копией открытым текстом.
4. Мигрировать через проверенную копию, атомарное переключение и сценарий восстановления при отключении питания. Не удалять старую базу до подтверждения чтения новой. Учесть, что удаление файлов на SSD не гарантирует физического стирания старых данных.
5. Проверить ошибочный пароль, повреждённый файл, переустановку, потерю Keystore, восстановление на другом устройстве, синхронизацию разных версий и отсутствие личного текста в новых файлах на диске. Открытый CSV/экспорт оставить отдельным явным действием.

## Проверки и границы

- `cargo test --locked --manifest-path src-tauri/Cargo.toml --lib`: 50 passed, 1 ignored (ручной сетевой тест каталога обложек), повторно после обновления библиотек.
- `node --test tests/*.test.mjs tests/*.test.cjs`: 22 passed. Новые проверки в `tests/security.test.mjs` подключены также к стандартному `npm run test:ui`.
- Общий UI-прогон выявил два устаревших ожидания тестов: смену даты при открытом редакторе и фиксированную ширину мобильных кнопок. Ожидания приведены к существующему поведению защиты черновика и адаптивной сетки, без изменения этих функций приложения. Повторно пройдены mobile UX (28), UX 0.4.22 (33), audit-fixes (24), очередь сохранения (12 + 3), преобразования/напоминания (20); оставшаяся часть проверена отдельными запусками после остановки общего сценария.
- Сценарий ИИ-обложек: проверено отсутствие запроса до кнопки, загрузка после кнопки и сохранение только после применения; 52 проверки в `tests/ui-0.4.18.cjs`.
- `npm run build`: успешно, остаётся предупреждение о размере JS bundle. `licenses:generate` и `licenses:check`: успешно после добавления notice обновлённого binding Rolldown.
- `cargo clippy --locked --offline --manifest-path src-tauri/Cargo.toml --lib -- -D warnings` и `cargo fmt --check`: успешно. Оригинальный whitespace обновлённых upstream-лицензий сохранён.
- База RustSec: commit `21d909e4c8bd4e14c7aea58bf980c881a0053ab1`, обновлена 24 октября 2026. Полный lockfile всё ещё содержит 5 предупреждений: proc-macro-error, zbus_names, zvariant, zvariant_derive (unmaintained), glib (unsound). Их нет в объединённом Cargo-графе Windows x64/Android ARM64, использованном для инвентаризации; для будущей Linux-сборки нужна отдельная работа. Предупреждения не подавлялись.
- Это статический обзор границ доверия и автоматические тесты, не независимый полный пентест. Реальные Android WebView/Keystore, физическое устройство, вредоносный речевой сервис, все транзитивные Maven-зависимости и установленный старый APK в этом проходе не проверены. APK/EXE с исправлениями ещё не собраны.
- Проверка не доказывает, что невозможно украсть данные: ссылки могут вести на фишинговые сайты, ИИ может ошибаться или подчиниться инструкции внутри текста, а пользователь может подтвердить опасное изменение. Предпросмотр, ограниченные команды и запрет автоматических сетевых запросов уменьшают этот риск.
