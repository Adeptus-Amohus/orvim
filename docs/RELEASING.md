# Подготовка выпуска

Текущий выпуск: [0.4.46](releases/0.4.46.md), [установка и обновление](INSTALLATION.md). Постоянный Android release-ключ создан с разрешения владельца; не создавайте новый при следующем выпуске. Основной проект, исходники, сайт и выпуски находятся в Adeptus-Amohus/orvim; life-os сохраняет прежнюю приватную историю. Существующий публичный тег v0.4.46 фиксирует прежние материалы распространения и не перемещается. Для исходников снимка 0.4.46 используется source-v0.4.46; при дальнейших выпусках tag и исходный commit приложения явно записываются в manifest/build-info. Это не включает канал автообновлений.

## Исходники и версия

Работайте с согласованным коммитом и чистым рабочим деревом. Обновляйте версию согласованно в package.json/package-lock.json, src-tauri/Cargo.toml/Cargo.lock и tauri.conf.json. Android получает versionName/versionCode через Tauri; проверьте значения в готовом APK. Для выпуска 0.4.46 подтверждён код 4046; для следующих обновлений увеличивайте его. Имя файла не подтверждает содержимое.

Сохраняйте local.lifeos.client и постоянный сертификат для обновлений release-установок. Переход с прежнего тестового сертификата на постоянный ключ 0.4.46 требует проверенной внешней копии и переустановки: [ANDROID_SIGNING.md](ANDROID_SIGNING.md). Для нового orvim.exe проверьте обновление прежних ярлыков life-os.exe и сохранность базы. Изменения после упаковки требуют новой сборки; ранее проверенный APK не подтверждает новые исходники.

## Проверки до упаковки

Выполните применимые проверки из [DEVELOPMENT.md](DEVELOPMENT.md#проверки). Отдельно запишите существующие сбои; зелёный Vite build не заменяет UI/Rust-тесты. Проверьте ручной сценарий создания, редактирования, завершения и сохранения записей после перезапуска на Windows и Android, а также копию и восстановление.

Обновите [лицензии](../third-party/README.md), включая Android runtime notices после изменения Kotlin/Gradle-зависимостей. Проверьте NOTICE, оригинальные OFL/copyright и доступность исходников MPL-компонентов.

После Android-сборки проверьте фактические транзитивные зависимости, а не только прямые объявления:

```powershell
./src-tauri/gen/android/gradlew.bat -p src-tauri/gen/android :app:dependencies --configuration universalReleaseRuntimeClasspath > android-runtime-dependencies.txt
node scripts/check-android-runtime-notices.mjs android-runtime-dependencies.txt
```

В 0.4.46 эта сверка покрывает 92 координаты, включая BOM metadata. Уведомления Jackson 2.15.3 и встроенных FastDoubleParser/bigint извлечены из точных runtime JAR и включены в общий комплект.

## Windows

```powershell
npm ci
npm run licenses:generate
npm run licenses:check
npm run desktop:build
npm run tauri -- build --bundles nsis
```

Результаты: src-tauri/target/release/orvim.exe и bundle/nsis. Переименовывать копию для выпуска можно после проверки её версии. Не выдавайте подпись манифеста обновлений за доверенную подпись издателя EXE. Проверяйте установленный и переносимый сценарии отдельно.

## Android

Настройте [JDK 21, SDK и NDK](ANDROID.md), затем:

```powershell
npm run android:check
npm run android:build -- --apk --target aarch64 --ci
```

Проверьте package name, minSdk/targetSdk, versionName/versionCode и состав ARM64. Release APK без подписи не предназначен для обычной установки. Примените сохранённый keystore вне Git; после выравнивания и подписи проверьте apksigner verify и 16 КБ-выравнивание средствами установленного SDK. Не публикуйте пароли в аргументах команд или отчёте. Проверяйте обновление поверх прежнего APK и сохранение данных на физическом устройстве.

## Комплект и публикация

Для Android desugar_jdk_libs действует GPLv2 с Classpath Exception. До публичного распространения подготовьте соответствующие исходники именно включённой версии и выполните условия их предоставления. Наличие текста лицензии и зелёный licenses:check не заменяют этот шаг. Условия и источник: [LICENSES.md](LICENSES.md#android-desugar_jdk_libs). Для MPL-компонентов сохраняйте указанные ссылки на исходники и предоставляйте собственные изменения при их наличии.

В папку выпуска положите EXE/установщик/APK, контрольные суммы SHA-256, сведения о коммите/версии/среде/подписи, заметки, LICENSE, NOTICE и THIRD_PARTY_LICENSES.txt. Публичные лицензии дополнительно встроены через public в интерфейс приложения.

Сохраните рядом инвентаризацию third-party/inventory.json и комплект соответствующих исходников/уведомлений, необходимый для включённых компонентов. Не помечайте этот комплект готовым только по результату автоматической проверки прямых зависимостей.

releases и .artifacts игнорируются Git. Git push сохраняет исходники, но не создаёт GitHub Release и не публикует эти файлы. CI Build Orvim загружает Actions artifacts; без настроенных signing secrets Android-артефакт помечен unsigned. Публичную публикацию выполняйте отдельным согласованным действием.

CI использует только постоянный release-ключ через secrets `ORVIM_ANDROID_KEYSTORE_BASE64`, `ORVIM_ANDROID_STORE_PASSWORD`, `ORVIM_ANDROID_KEY_PASSWORD`, `ORVIM_ANDROID_KEY_ALIAS` и проверяет закреплённый отпечаток. Прежние тестовые signing secrets больше не используются. Наличие локального keystore не означает, что эти secrets настроены в GitHub; автоматически загружать ключ в CI не требуется. Без них CI проверяет сборку и явно выдаёт unsigned artifact; в GitHub Release загружается отдельно проверенный подписанный APK.

Для автоматического канала нужны опубликованные HTTPS-пакеты, открытый ключ в сборке и подписанный манифест. Закрытый ключ подписи и APK keystore — разные секреты, оба хранятся вне репозитория. [UPDATES.md](UPDATES.md).
