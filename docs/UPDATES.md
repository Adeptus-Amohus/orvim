# Настройка подписанных обновлений

Для выпуска 0.4.47 используется ручная установка из [публичного GitHub Release Orvim](https://github.com/Adeptus-Amohus/orvim/releases/tag/v0.4.47) без авторизации. Автоматический подписанный канал отдельно не включён. Постоянная Android-подпись отличается от тестовых APK до 0.4.45: [переход и сохранение данных](INSTALLATION.md#переход-со-старого-тестового-apk). Исторические указания ниже о сохранении прежнего тестового сертификата относятся к тестовым выпускам.

Обновление работает через подписанный Ed25519 манифест `orvim-updates.json`. В приложение встраивается только открытый ключ. Манифест подписывает список версий, SHA-256, размер и HTTPS адрес каждого установщика; приложение проверяет подпись, а затем содержимое пакета. Подменённый пакет не запускается.

## Один раз

1. Создайте ключ **вне репозитория**, не передавайте его в чат:

   ```powershell
   node scripts/update-key.mjs (Join-Path $env:USERPROFILE '.orvim-keys\update-private.pem')
   ```

2. Сохраните показанный открытый ключ в переменную сборки `ORVIM_UPDATE_PUBLIC_KEY`. Для CI это GitHub variable; закрытый ключ — отдельный GitHub Actions secret либо офлайн файл. Ограничьте доступ к файлу ключа средствами Windows и сохраните независимую защищённую копию. Ключ подписи создан локально вне репозитория; открытая часть сохранена в src-tauri/update-public-key.txt и встроена в сборки 0.4.27. Закрытый ключ не должен попадать в Git или приложение.
3. Пересоберите Windows и Android с этим открытым ключом. У Android сохраните **тот же APK keystore**, которым подписана установленная версия. Смена сертификата исключает установку поверх приложения.
4. Разместите пакеты в GitHub Release; используйте tag, например `v0.4.23`, с окончательными HTTPS адресами.

## Манифест

Для будущего подписанного канала подготовьте JSON (хеш, размер и ограничения схемы должны соответствовать фактическим файлам). Ниже пример, а не включённый канал 0.4.46:

```json
{
  "manifest_version": 1,
  "releases": [
    {
      "version": "0.4.46",
      "notes": "Сохранение, ИИ, синхронизация, копии",
      "schema_min": 3,
      "schema_max": 3,
      "workspace_max": 32,
      "platforms": {
        "windows-x86_64": {
          "url": "https://github.com/Adeptus-Amohus/orvim/releases/download/v0.4.46/Orvim-0.4.46-Windows-x64-setup.exe",
          "sha256": "REPLACE_WITH_REAL_SHA256",
          "size": 1
        },
        "android-aarch64": {
          "url": "https://github.com/Adeptus-Amohus/orvim/releases/download/v0.4.46/Orvim-0.4.46-Android-arm64.apk",
          "sha256": "REPLACE_WITH_REAL_SHA256",
          "size": 1
        }
      }
    }
  ]
}
```

Здесь заглушки обозначены явно; такой манифест приложение отклонит.

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'releases\0.4.46\Orvim-0.4.46-Windows-x64-setup.exe'
$env:ORVIM_UPDATE_PRIVATE_KEY_FILE = Join-Path $env:USERPROFILE '.orvim-keys\update-private.pem'
node scripts/sign-update-manifest.mjs unsigned-updates.json orvim-updates.json
Remove-Item Env:ORVIM_UPDATE_PRIVATE_KEY_FILE
```

Опубликуйте подписанный файл рядом с пакетом в последнем GitHub Release. В готовых сборках 0.4.46 адрес по умолчанию по-прежнему относится к приватному life-os, с резервным orvim-updates; это не публичный канал Orvim. Публикация APK/EXE в orvim не меняет встроенные адреса и не включает автообновления. Для будущего канала задайте доступный публичный `ORVIM_UPDATE_MANIFEST_URL` при следующей сборке и проверьте всю подписанную цепочку. Включайте предыдущие совместимые версии в тот же подписанный список, чтобы они отображались в приложении.

## Установка и откат

Windows запускает проверенный NSIS установщик после создания копии и завершает текущий процесс. Системные подтверждения остаются у пользователя. Откат разрешён только при заявленной совместимости со схемой 3 и документом 32. При несовместимости автоматический запуск заблокирован: сначала понадобится подходящий снимок, его восстановление требует подтверждения потери более поздних изменений.

Android проверяет package name и сертификат APK, открывает системную установку и при необходимости настройки разрешения установки из Orvim. Обычный Android запрещает downgrade к более низкому versionCode. Безопасный ручной путь: выбрать внешнюю папку копий, создать и проверить копию, сохранить предыдущий APK вне приватной папки приложения, удалить приложение, установить APK и восстановить совместимую копию. Автоматическое удаление приложения не выполняется.

Открытый ключ манифеста сохранён в src-tauri/update-public-key.txt; локальная подготовка подписанных обновлений реализована. Это не подтверждает наличие публичного канала. Публикация ранее отложена по решению владельца; перед запуском требуется проверить доступные без авторизации URL и всю цепочку установки. Тестовые APK 0.4.35 используют существующий debug-сертификат. Порядок перехода на постоянную подпись описан в [ANDROID_SIGNING.md](ANDROID_SIGNING.md).

## Проверка без автоматического канала

Если открытый ключ ещё не встроен, кнопка проверяет публичный последний выпуск через GitHub API. Она сообщает номер установленной и новой версии и открывает страницу выпуска для ручной установки. Такая проверка не разрешает запуск неподписанного пакета. Недоступный или закрытый репозиторий не считается доказательством отсутствия обновлений.

Новые переменные сборки имеют префикс `ORVIM_UPDATE_`. Старые `LIFE_OS_UPDATE_PUBLIC_KEY`, `LIFE_OS_UPDATE_MANIFEST_URL` и переменные закрытого ключа пока принимаются для совместимости с существующей настройкой. Адрес репозитория не переименовывается локальной правкой исходников.

## История проверки канала в 0.4.27

При подготовке 0.4.27 было подтверждено через GitHub API с авторизацией (это исторический результат, не новая проверка доступности): Adeptus-Amohus/life-os приватный, выпусков при проверке нет. Неавторизованное приложение получает 404. Сборки поддерживают проверку life-os и отдельного публичного канала Adeptus-Amohus/orvim-updates; оба требуют тот же ключ подписи. Публикация/изменение видимости требует решения владельца. Ни личный GitHub-токен, ни закрытый ключ подписи в APK/EXE не включаются.

После упаковки: node scripts/prepare-update-release.mjs releases/0.4.27 OWNER/REPOSITORY; затем scripts/sign-update-manifest.mjs подписывает полученный unsigned JSON ключом вне репозитория. Перед выпуском убедитесь, что APK/EXE, orvim-updates.json и ссылки опубликованы и доступны без входа в GitHub. Пользователь подтверждает установку системным установщиком; тихая установка Android не обещается. Старые 0.4.26 и более ранние сборки требуют одного ручного обновления до версии с доверенным ключом.
