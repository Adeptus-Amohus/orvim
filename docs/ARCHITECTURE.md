# Текущая архитектура

## Платформы и границы

Windows и Android используют Tauri 2, один React/Vite интерфейс и общие модули логики. src/app/FullApp.tsx монтирует workspace, подключает нативные службы и очередь сохранения. HTML-разметка, CSS и функции основного UI находятся в src/features/workspace.

native.ts выбирает Tauri IPC или отдельный браузерный адаптер IndexedDB. Нативные возможности не эмулируются реальными API-ключами в браузере. Старые src/domain, src/application и прежние экраны MVP остаются в дереве; они не являются полным описанием текущего workspace.

## Сохранение

persistence.ts последовательно записывает снимки, объединяет ожидающие изменения и отслеживает revision. Ошибка записи остаётся видимой, ожидающие данные можно отправить повторно. Закрытие Windows ожидает flush; Android передаёт события паузы. Отсутствие подтверждения сохранения нельзя считать завершённой записью.

Rust commands.rs сериализует доступ к Repository. storage/workspace.rs валидирует документ, ссылки, диапазоны и сохраняет его транзакцией. SQLite открывается с foreign_keys=ON, journal_mode=WAL и synchronous=FULL.

## Модель данных

Есть три независимых номера:

| Что               | Текущее значение | Значение                              |
| ----------------- | ---------------- | ------------------------------------- |
| Версия приложения | 0.4.36           | Метаданные сборки                     |
| Схема SQLite      | 3                | Миграции в src-tauri/migrations       |
| Формат workspace  | 32               | Структура документа и резервной копии |

В WorkspaceDocument входят revision, data и covers. data содержит 20 коллекций: tasks, events, checkins, projects, sleepLogs, foodLogs, workouts, recoveryLogs, waterLogs, trainingGoals, archiveItems, savedMeals, taskTemplates, thoughts, financeLogs, exercises, stepLogs, weightLogs, illnessLogs, nutrientLogs. Название recoveryLogs сохранено для совместимости; его наличие не означает отдельный текущий экран восстановления.

Рабочие данные, настройки, коллекции и обложки сохраняются через текущий repository; прежние таблицы MVP сохраняются миграциями. Неизвестная более новая схема/формат вызывает ошибку, а не создание пустого состояния. Старые документы проходят поддержанные преобразования на границе загрузки. Точные поля и ограничения задаются кодом валидации, а не историческим DATA_MODEL.md.

## Каталоги и совместимость

Идентификатор приложения — local.lifeos.client. Папка берётся из Tauri app_local_data_dir. При наличии life-os.sqlite3 используется она; иначе создаётся orvim.sqlite3. В Windows копии идут в существующую Documents/Life OS/backups либо новую Documents/Orvim/backups. На Android приватные копии находятся рядом с данными, внешние — через SAF.

Старые идентификаторы резервных копий, IPC-событий и защищённого хранилища намеренно сохраняются. Переименование бренда не является миграцией пользовательской базы. [Копии](BACKUPS.md), [приватность](PRIVACY.md).

## Необязательные службы

- assistant.rs валидирует действия по actions-schema.json; connections.rs выполняет запросы к выбранному провайдеру. Ответ не исполняется как SQL или произвольная команда.
- lan/ реализует сопряжение, шифрование, обмен, сравнение и конфликты в общей локальной сети. [Синхронизация](SYNC_0_4.md).
- backups.rs создаёт и проверяет копии. updates.rs проверяет подпись манифеста и пакет до запуска установщика.
- platform.rs и Android OrvimPlugin/OrvimHealthConnect/OrvimBackups обеспечивают платформенные адаптеры. Старый модуль OrvimDictation остаётся в исходниках, но текущий чат не вызывает диктовку; RECORD_AUDIO удалено из манифеста. Ввод речи выполняет клавиатура ОС.
- media.rs ограничивает HTTPS-источники обложек и размер/время загрузки.

Установки не зависят от сервера Orvim. Внешние API и локальная сеть обмена имеют собственные условия доступности.

## Личный день и добровольные показатели

`life-tracking-model.js` задаёт границы личного дня по местным часам и календарным датам. Интервал не фиксирован в миллисекундах: при переводе часов он может составлять 23 или 25 часов. События с временной меткой группируются по этому интервалу; записи только с датой сохраняют её. Расписание продолжает использовать реальные календарные даты. Для сна используется дата пробуждения, для занятия — начало занятия.

`lifePreferences` содержит начало дня и настройки добровольных показателей. В интерфейсе питания переключаются вода, вес и БЖУ; калории остаются. Старые поля веществ сохраняются для совместимости. `life-tracking.js` создаёт их интерфейс. В Health Connect передаётся `dayStartMinutes`; ежедневные шаги агрегируются с этой границей. Автоматические итоги помечаются своей границей, чтобы не смешивать несовместимые суммы после смены режима. Оценка сложности относится ко всему занятию: `workout.effort` (1–5), с `effortRatedAt`. Это добровольная оценка выполненного занятия.

Болезнь не подделывает выполнение: реальные результаты остаются, невыполненные занятия в отмеченный период исключаются из знаменателя выполнения плана. Статистика шагов сохраняет общий итог и отдельно считает среднее вне болезни. Контекст ИИ включает выбранные показатели веса и болезни только при выборе соответствующего источника или всех данных «Жизни».

Новые коллекции входят в обычное шифрованное хранилище, резервные копии, локальную синхронизацию и сравнение файлов. Сетевой протокол 4 и версия файла переноса 2 защищают новые поля от обработки несовместимым старым приложением; новый клиент читает прежний формат файла 1.
