# Резервные копии и восстановление

## Виды копий

С версии 0.4.24 база и автоматические копии в установленном приложении зашифрованы ключом устройства. Их нельзя считать переносимыми: после переустановки ключ может быть потерян. Используйте **Настройки → Данные → Копия с паролем** для независимого восстановления на другом устройстве. Пароль храните отдельно; приложение его не сохраняет. Автоматическое зеркалирование во внешнюю папку отключено, поскольку копии с ключом устройства не восстанавливаются после удаления приложения. Старые внешние копии могут оставаться открытыми.

**Обычный JSON/CSV экспорт не зашифрован.** Восстановление защищённой копии доступно в настройках, а при ошибке открытия базы — на стартовом экране. Версии до 0.4.24 не читают новый зашифрованный файл SQLite напрямую. [Подробности защиты](ENCRYPTION.md).

| Вид                   | Для чего                                                        | Ограничения                                                              |
| --------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------ |
| JSON из настроек      | Перенос рабочего пространства и восстановление через приложение | Восстановление заменяет рабочее пространство; нужен предпросмотр         |
| Автоматический снимок | Периодические снимки и копии перед важными действиями           | Хранятся последние 24 управляемые копии; это не отдельный архив навсегда |
| SQLite-снимок         | Согласованная копия перед сменой версии/миграцией               | Создаётся через VACUUM INTO; не заменяйте рабочую базу наугад            |
| CSV                   | Просмотр/анализ экспортированных данных                         | Не полная резервная копия                                                |
| LAN                   | Обмен между установками                                         | Удаления и ошибки тоже могут распространяться; обмен не заменяет копии   |

Копии включают рабочие записи и обложки; настройки подключений/секреты исключаются штатной подготовкой снимка. Текст, в который пользователь сам вставил пароль, автоматически не распознаётся как секрет. Автоматические копии защищены ключом устройства; переносимые копии с паролем — заданным пользователем паролем. Обычный экспорт JSON/CSV остаётся открытым.

## Где находятся

- **Windows:** существующая папка Документы/Life OS/backups сохраняется; иначе используется Документы/Orvim/backups. Папка Документы может быть перенаправлена настройками ОС.
- **Android:** приватные automatic-backups в каталоге приложения. Для независимой копии используйте «Копия с паролем» и сохраните файл вне каталога приложения через системный диалог.
- **Экспорт:** выбранное пользователем место. Храните независимую копию вне устройства.

Переименование Life OS в Orvim не перемещает существующую базу и не требует ручного удаления старой папки.

## Проверенный перенос

1. Дождитесь подтверждения сохранения на исходном устройстве.
2. Откройте Настройки → Данные, создайте копию с паролем.
3. Сохраните файл в независимом месте; проверьте дату и размер.
4. На принимающем устройстве установите совместимую версию.
5. Выберите импорт/восстановление, прочитайте предпросмотр замены и подтвердите.
6. Проверьте записи и обложки, перезапустите приложение и проверьте их повторно.

Не удаляйте исходную установку до проверки результата. Ключи провайдеров на втором устройстве вводятся отдельно.

## Совместимость и восстановление после ошибки

Текущие номера: схема SQLite 3 и документ 32. Номер приложения сам по себе не гарантирует совместимость более старого клиента. Более новые неподдерживаемые данные должны давать ошибку, а не пустое пространство.

Если появилось пустое состояние или ошибка, остановите обмен, сохраните доступные копии и исходные файлы, запишите версию и шаги. Не удаляйте приложение и не подменяйте открытую SQLite вместе с WAL/SHM. Используйте штатный менеджер восстановления; перед заменой создайте ещё один снимок.

Android downgrade к меньшему versionCode может блокироваться системой. Ручной сценарий и требования к подписи: [UPDATES.md](UPDATES.md#установка-и-откат). Полное удаление данных необратимо для выбранных локальных файлов и не является способом проверки восстановления.

Автоматическая история: после изменений во время работы приложения сохраняется не чаще одного снимка в час. При перезапуске или перед важной операцией возможны дополнительные копии. Сохраняются 24 последних снимка, независимо от того, за сколько дней они созданы. Старые заменяются. Эта история нужна для восстановления после ошибки; для переноса на другое устройство нужна копия с паролем. CSV предназначен для анализа и не содержит всех данных для восстановления.
