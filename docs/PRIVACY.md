# Данные и приватность

Документ сверён с рабочими исходниками Orvim 0.4.35 и последующими изменениями 4 ноября 2026; это не обещание условий сторонних сервисов.

## Что хранится на устройстве

SQLite содержит задачи, проекты, мысли, личные записи, финансы, результаты тренировок, настройки и обложки. Переписка помощника и сохранённый контекст также могут входить в рабочие данные и копии. Установки Windows и Android имеют самостоятельные базы.

Выбор языка интерфейса отдельно кэшируется в localStorage (`orvim-interface-language`), чтобы экран загрузки и ошибки до открытия базы показывались на выбранном языке. Это незашифрованная настройка `ru` / `en` / `system`; записей пользователя, переписки и ключей в ней нет.

В помощнике «Данные для ИИ» сохраняет явно выбранные разделы и записи между открытиями чата и перезапусками. Они передаются при следующей отправке сообщения, с учётом выбранного периода. Весь раздел включает новые записи этого раздела. Чтобы отозвать выбор, откройте «Данные для ИИ» → «Убрать всё»; очистка переписки также сбрасывает выбор. Просмотр содержимого запроса доступен внутри выбора данных. Само открытие чата ничего не отправляет.

Папку определяет ОС через Tauri app_local_data_dir для local.lifeos.client. Новая база называется orvim.sqlite3; при наличии старой life-os.sqlite3 приложение продолжает использовать её. Браузерный просмотр хранит отдельную IndexedDB life-os-preview; очистка данных браузера может удалить её.

Установленное приложение шифрует основную базу и внутренние автоматические копии ключом устройства. Для переноса и восстановления после переустановки предназначена отдельная копия с паролем. Обычный экспорт JSON/CSV, отдельно сохранённые вложения и браузерный предпросмотр остаются открытыми. Старые внешние копии не переписываются автоматически. [Копии и восстановление](BACKUPS.md), [технические границы защиты](ENCRYPTION.md).

## Ключи и разрешения

API/OAuth-секреты хранятся отдельно от обычного экспорта: DPAPI в Windows и платформенное защищённое хранилище Android. Настройки подключения очищаются из подготовленных снимков; ключи не нужно вставлять в мысли, сообщения и заметки — такие тексты считаются обычными данными и могут попасть в копию или выбранный контекст.

Ключ «Другого JSON API» привязан к HTTPS origin (схема, хост, порт), указанному при сохранении. При смене сервера ключ нужно сохранить заново; старые ключи без привязки не отправляются до повторного сохранения. Пути API внутри того же origin могут различаться. Переадресации запросов с ключом не выполняются.

Шифрование LAN защищает передачу. Локальные SQLite-журналы синхронизации также зашифрованы; при обновлении существующие журналы переводятся на защиту.

Разрешения уведомлений, календаря, камеры для QR и Health Connect запрашиваются для соответствующих действий. Разрешения можно отозвать в ОС. В текущих исходниках встроенная диктовка удалена из чата, а разрешение RECORD_AUDIO — из Android-манифеста. Голосовой ввод возможен через клавиатуру/службу ввода ОС: она обрабатывает аудио по своим настройкам. Orvim получает введённый текст; выбранный ИИ получает его только при отправке. Ранее собранные пакеты 0.4.35 ещё содержат прежнюю диктовку.

## Когда используется сеть

| Действие                         | Куда и что передаётся                                                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Проверка ИИ-ключа/списка моделей | Выбранному провайдеру: данные авторизации и запрос списка, без рабочего пространства                                               |
| Запрос ИИ                        | Запрос, переписка/контекст, выбранные в интерфейсе данные и инструкции провайдеру                                                  |
| Поиск/получение обложек          | Название и запрос каталогу; затем запрос изображения разрешённому хосту                                                            |
| Notion/JSON API/Google Calendar  | Запросы и данные соответствующего импорта/экспорта с авторизацией                                                                  |
| LAN                              | Зашифрованные записи и метаданные сопряжённому устройству в сети                                                                   |
| Проверка обновлений              | Запрос к GitHub или настроенному HTTPS-каналу; авторизация GitHub из локального Git не даёт приложению доступ к приватным Releases |

Основные локальные разделы не требуют этих подключений. В коде приложения не настроен отдельный сервис аналитики Orvim; это не описывает телеметрию ОС, WebView, речевого движка или подключённых провайдеров.

Health Connect читается на Android после разрешения; импортированные записи становятся локальными данными Orvim. Если позже выбрать их для ИИ, синхронизации или экспорта, они могут покинуть устройство через выбранное действие. [Health Connect](HEALTH_CONNECT.md).

## Удаление и перенос

Удаление записи может передаваться сопряжённым устройствам, но не стирает независимые старые копии. Полное удаление данных в приложении затрагивает локальные записи, настройки, ключи, сопряжения и внутренние копии по подтверждению; экспортированные отдельно файлы остаются у пользователя; оно не удаляет автоматически данные другого устройства или внешнего сервера. Удаление приложения Android удаляет приватные данные, а не выбранную внешнюю папку.

Отзывайте ненужные ключи у провайдеров, отключайте синхронизацию и проверяйте содержимое экспорта перед передачей. Пользовательские записи не становятся лицензированными под Apache-2.0 из-за хранения в Orvim. [Лицензии](LICENSES.md), [безопасность](../SECURITY.md).
