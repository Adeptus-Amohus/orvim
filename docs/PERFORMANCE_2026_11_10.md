# Запуск и отрисовка Orvim · 10 ноября 2026

Изменения выполнены поверх существующего рабочего дерева 0.4.44. Размер установочных пакетов не оптимизировался.

- Обычная загрузка показывает только существующую керамическую эмблему с вращением и тонкую неопределённую полосу под ней. Текст остаётся для ошибок и восстановления. При системной настройке уменьшения движения анимация отключается.
- Небольшая оболочка запуска загружается отдельно от рабочего пространства. Главный JS до загрузки пространства уменьшился с 1012 до 227 КБ; общий объём приложения практически не изменился. Это разделение загрузки, а не уменьшение пакета.
- Устранён цикл между переводом и подписями округлённых полей: подпись уже содержит локализованный текст и пользовательское значение. Повторный перевод вызывал обновления каждый кадр, в том числе в покое.
- Русский интерфейс не обходит повторно все текстовые узлы при каждом рендере. Полный обратный перевод сохраняется при смене английского на русский. После установки модулей кэшируется обратный словарь.
- Поля отслеживают изменения самих полей, их вариантов и подписей, а не любую смену узла во всём приложении. Подпись читается обходом текста без клонирования содержимого `label`.
- Форматирование дат и чисел использует ограниченные кэши `Intl` во всём пространстве: календарь, списки, питание, финансы, рейтинги и тренировки.
- Готовые SVG-иконки сохраняются при повторной отрисовке. Геометрия клонируется из шаблона только для новых или изменившихся иконок.
- Убраны повторные начальные отрисовки. Списки скрытых экранов строятся при открытии. Повторные запросы сохранения от обработчиков одного события объединяются в микрозадачу; очередь записи и ревизии не изменены.
- Перемещения при перетаскивании объединяются до одного обновления за кадр с обработкой последней позиции при отпускании. Призраки перемещаются через `transform`; автопрокрутка учитывает время кадра вместо фиксированного расстояния на кадр. Количество незавершённых дел по проектам считается одним проходом.
- Минутное обновление интерфейса пропускается в скрытом документе. Обновление при возврате сохраняется.
- На Android 15+ WebView запрашивает высокую категорию частоты через `View.setRequestedFrameRate`. На предыдущих версиях выбирается наибольшая доступная частота текущего разрешения через `preferredRefreshRate`. Фиксированный таймер на 60 FPS не добавлялся.

API Android сверены с [ARR](https://developer.android.com/develop/ui/views/animations/adaptive-refresh-rate) и [WindowManager.LayoutParams](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#preferredRefreshRate). Это предпочтение для системы: доступные 90/120 Гц зависят от телефона, WebView, системных настроек и энергосбережения. Частота дисплея и число фактически отрисованных кадров — разные показатели.

## Замеры

Production Vite build, headless Chrome на этом Windows-компьютере, чистый отдельный браузерный контекст для каждого запуска, три запуска на сценарий. В таблице медиана времени от навигации до снятия `hidden` с рабочего пространства. Мобильный сценарий означает ширину окна 390 px; Android WebView и реальный телефон здесь не измерялись.

| Сценарий                                     |     До |  После | Ускорение |
| -------------------------------------------- | -----: | -----: | --------: |
| Пустая база, desktop 1440 px, RU             | 239 мс | 178 мс |       26% |
| Пустая база, viewport 390 px, RU             | 232 мс | 165 мс |       29% |
| История: 1000 задач, 20 проектов, desktop RU | 240 мс | 164 мс |       32% |
| Пустая база, desktop EN                      | 249 мс | 193 мс |       22% |

Первое отображение содержимого, медиана: 72–84 мс до, 44–48 мс после. Самый первый запуск Chrome даёт отдельный выброс; он включён в исходные три результата, но не определяет медиану.

В английском интерфейсе работа основного потока за 800 мс покоя снизилась с 809 до 2,5 мс. Отдельная браузерная проверка после открытия базы данных и возврата на главную обнаружила **0 DOM-изменений за 800 мс**. В сценарии истории фоновая работа не улучшилась: около 3,6 → 4,1 мс, что не является обещанием снижения всех метрик.

Исходные результаты и CPU-профили: `.artifacts/performance/before.json`, `after.json`, соответствующие `.cpuprofile`. Повторить при работающем `npm run preview -- --host 127.0.0.1 --port 5182 --strictPort`:

```powershell
node scripts/benchmark-startup.cjs .artifacts/performance/current.json
node tests/browser-performance.cjs
```

`ORVIM_BENCH_URL` меняет адрес, `ORVIM_BENCH_RUNS` — число повторов. Бенчмарк использует синтетические данные только в изолированном IndexedDB браузера.

## Проверки

- `npm run build`: TypeScript и production frontend собраны.
- `npm run desktop:build`: успешно; `src-tauri/target/release/orvim.exe`, 19 299 840 байт. Для OpenSSL использован уже находившийся в проекте переносимый Strawberry Perl из `.artifacts/strawberry/perl/bin`, добавленный в PATH только процесса сборки. Установленное приложение не запускалось и не заменялось.
- `npm run test:ui`: полный набор DOM/логики и очереди сохранения прошёл, включая новый `performance.test.mjs`.
- `node tests/browser-performance.cjs`: реальная production-страница, 1440×900 и 390×844, загрузка без текста, вращение, reduced motion, навигация, питание/сон/тренировки/финансы, прекращение английского цикла, сохранение пользовательского имени коллекции, повтор загрузки после асинхронной ошибки IndexedDB. Ошибок JavaScript нет.
- `node tests/browser-english.cjs`: 24 проверки переключения EN → RU → EN на ширинах 320/390/1440; пользовательские заголовки сохранены.
- Android `:app:compileArm64ReleaseKotlin -x rustBuildArm64Release`: успешно с локальным JDK `temurin-21.0.12.1+1`. Это компиляция Kotlin/Java и ресурсов, не сборка нового APK. Исходный `JAVA_HOME` указывал на Java 25; глобальная настройка не менялась.

Скриншоты проверены: `.artifacts/performance/loading-desktop.png`, `loading-mobile.png`, `workspace-desktop.png`, `workspace-mobile.png`. На физическом телефоне проверки не проводились; стабильные 90/120 FPS не подтверждены. Эти замеры также не подтверждают ускорение нативного открытия зашифрованной SQLite-базы или работы внешних сервисов.
