# Синхронизация 0.4

## Один роутер

ПК может быть подключён кабелем Ethernet, телефон — по Wi-Fi. На ПК: Настройки → Данные → Создать подключение. На телефоне: Найти устройства → выбрать ПК → сравнить его идентификатор → ввести одноразовый код. Альтернатива: камера телефона → QR → подтверждение подключения в Orvim. Код действует 5 минут и применяется один раз; ручной адрес остаётся запасным вариантом.

Сервер слушает все интерфейсы (`0.0.0.0`), обнаружение опрашивает IPv4 интерфейсы с их broadcast адресами. В Windows разрешите Orvim в **частной** сети: TCP 42673 и UDP 42674. Гостевой Wi-Fi, AP/client isolation, VPN или firewall могут блокировать связь даже на одном роутере. При нескольких адресах QR использует первый; если он недоступен, воспользуйтесь обнаружением либо запасным адресом. Оба приложения должны быть открыты.

SPAKE2 подтверждает общий код, затем обмен защищён XChaCha20-Poly1305 с разными направлениями и challenge. Отдельный ID выбранного ПК сверяется до сохранения сопряжения. QR не делает обмен незашифрованным.

## Перед применением

Входящие добавления, правки и удаления ждут сравнения. Нажмите «Сравнить изменения», проверьте локальную/входящую версии и оставьте флажки у выбранных записей. Конфликты сохраняют варианты; для задач, событий, мыслей и материалов можно сохранить локальную версию отдельной копией. Перед применением создаётся резервная копия.

Отклонение запоминается для конкретной версии записи и не отправляет скрытое удаление другим устройствам. Новое изменение той же записи может снова потребовать сравнения. После сохранения только тогда подтверждается receipt. Журнал содержит UUID, отметки полей, tombstones и pending операции; повторная передача не создаёт дубликаты. Локальные настройки, API ключи и оформление не передаются.

## Безопасность сети

Записи передаются только после сопряжения. Восемь цифр кода действуют 5 минут; разрешено до 5 попыток, успешный код используется один раз. SPAKE2 согласует ключ, XChaCha20-Poly1305 шифрует содержимое и обнаруживает подмену, новый challenge каждого соединения блокирует повтор старого запроса. Отзыв устройства запрещает новый обмен с прежним ключом.

Сосед по Wi-Fi может видеть адреса, обнаружение устройства, время и объём трафика; эти метаданные не скрываются. Защита трафика не защищает от вредоносного ПО на уже разблокированном ПК/телефоне и от человека, которому пользователь сам передал действующий код. Код следует передавать лично между своими устройствами.

Обмен между разными сетями удалён. Старые настройки и журналы WebDAV больше не используются для сетевого обмена; их имена сохранены только для удаления/обработки старых файлов.

Проверены TCP-сопряжение, неверный код и ключ, одноразовость кода, изменение шифртекста, неправильное направление сообщения, повтор старого запроса на новом соединении, отзыв устройства и UDP-обнаружение. Это автоматические проверки на loopback; полноценный внешний пентест и перехват на настоящем домашнем роутере не проводились.

## Перенос без сети через файл

Настройки → Данные → Перенос по USB: подготовьте защищённый файл, сохраните вне приватной папки, скопируйте по кабелю и выберите «Открыть файл и объединить» на другом устройстве. Это файловый перенос, а не автоматическое подключение к USB. Совпадающие записи объединяются по идентификаторам; конфликтующие версии показываются для выбора. Название записи само по себе не является идентификатором. Пароль файла не передавайте вместе с ним посторонним.

Пользователь сообщил об успешном переносе с телефона на ПК без замеченных дублей. Проверка искусственного конфликта и повторного импорта остаётся отдельным сценарием: [готовность к релизу](RELEASE_READINESS.md).
